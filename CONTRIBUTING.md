# Contributing

Use Node.js 22.12+ and run `npm install`, `npm test`, and `npm run build`. Start `npm run dev` to check the interface. Validate changes in both themes and at desktop/mobile widths, using keyboard input as well as pointer controls.

GitHub Actions runs `npm ci`, `npm test`, `npm run typecheck`, `npm run registry:validate`, `npm run build`, and `npm run ci:smoke` on Ubuntu, Windows, and macOS with Node.js 22.12.0. Runs start on pushes to `main`, pull requests, or manual dispatch; superseded runs are cancelled. Jobs have a 20-minute timeout and read-only repository permissions.

To reproduce the packaged check locally, run `npm run build` then `npm run ci:smoke`. The Node script discovers the tarball through `npm pack --json`, installs it into an isolated temporary tools directory, moves that installation to another directory, runs the installed `design-studio` bin entry with `--help`, and starts it with implicit default `dev`, `--no-open`, and no `--project` from a React/Vite fixture in a path containing spaces. It checks the editor HTTP endpoint, built JS/CSS, a bundled font, and the actual ordinary-variable website preview and inferred mappings, then stops the process and removes temporary files even on failure. It invokes the package's JS executable through Node to avoid platform-specific shell wrappers. npm dependency installation requires network access; font downloads, credentials, a browser, a global install, and npm publication are not needed.

Keep configuration as the source of truth. Changes to schema, token derivation, exports, or mappings must also reach the CLI, preview, example configuration/skill, and documentation. Regenerate examples with the shared functions after changing defaults. A schema-breaking change needs an explicit version/migration; do not silently reinterpret saved configurations.

New adapters need tests proving dry-run does not write, apply preserves unrelated rules/comments/local edits, unsupported patterns fail safely, and retries cannot overwrite changes since planning. Never execute inspected code or read environment/secrets for analysis. Do not introduce source uploads, telemetry, network font requirements, or API-key requirements into the core workflow.

For bug reports, include Node/OS versions, the command or editor flow, and a minimal sanitized CSS/config fixture. Avoid uploading a whole private project or secret files. Submit focused changes with relevant validation. Run npm pack and globally install the resulting tarball with an isolated prefix on PATH before release. Verify bare `design-studio`, launch options and help from a separate React/Vite project with spaces in its path. Verify the website after stopping Design Studio, including fonts and safe rollback. Do not publish to npm or deploy without explicit authorization.

For presets, start with [the template](examples/preset-template.json) and follow [the registry contribution/update workflow](docs/presets.md). Run `npm run registry:validate` in addition to the normal checks. License changes require review of the actual pinned files and an update to README’s Design Sources and Attribution table, THIRD_PARTY_NOTICES.md, licenses/, and machine-readable provenance.

Actual-project regressions must include a rendered browser check, not only HTTP/CSS assertions: packed installation outside the website, bare launch from cwd, mapped visible computed colors, fonts loaded in the iframe, supported themes, HMR/navigation, Save/Reopen/Prompt/Skill consistency, reviewed Apply, independent development and production startup, and rollback. Include ordinary-variable and no-token CSS fixtures; select bounded migrations explicitly for the latter. Never claim the reporting user’s website was tested without its path and a real run.

Optional rendered regression: after `npm run build`, run `npm run test:browser` with a locally available Playwright runner and Chromium. A developer can explicitly prepare it with `npm install --no-save --package-lock=false playwright` and `npm exec playwright install chromium`. Alternatively set `STUDIO_PLAYWRIGHT_MODULE` to an existing Playwright module; `STUDIO_BROWSER_CHANNEL=chrome` uses installed Chrome. This is an opt-in development check, not a CLI dependency or a requirement for the default GitHub CI. It repeats the packed isolated workflow for ordinary-variable and no-token fixtures, uses bundled Noto fonts, checks actual computed colors/font loading, saved configuration/prompt/skill consistency, reviewed Apply, independent development/production and rollback. It installs fixture dependencies explicitly and cleans up all processes and temporary files on failure.
